# VERIFICATION_GATE.md — The Final, Blocking Gate

**Read once now, alongside `MASTER_PROMPT.md §11`; re-read before you say anything is finished.**
**Authoritative for, and only for:** the single question "is this ready to submit." `IMPLEMENTATION.md §Phase 9`, `ENGINEERING_REFERENCE.md §14/§17`, and `PRD.md §12` remain correct about *what* to check — this file is the evidence standard that decides whether checking it was enough, and the order to do it in.

---

## 0. Why this file exists

The rest of the document set is unusually thorough about *what* "WindLens" must be. It is comparatively soft about one thing: an autonomous agent can satisfy every checkbox in a checklist by *asserting* it, without having executed anything, and a chain of "run the audit, then report completion" instructions doesn't catch that on its own. Three rules close that gap, and apply everywhere else in this document set too:

1. **A check is not passed until you have personally run the command, in this build, and are pasting its real output.** Not "this should pass." Not "this is the kind of thing that works." The actual output.
2. **A capability you don't have is not a check you silently skip.** It is a named row in `docs/AGENT_CAPABILITIES.md`, carried forward to Tier 2.
3. **Nothing is "done" until the whole gate is green**, and the words "done" / "ready" / "complete" / "finished" / "you can submit now" do not appear anywhere — to the user, in commit messages, in `HUMAN_ACTIONS.md`, in `docs/AUDIT.md` — before that.

## 2. Tier 1 — Agent-verifiable (must be evidenced, no exceptions)

Run in this order. Each line is pass/fail with pasted evidence — a description of what *should* happen is not evidence.

### 2.1 Data integrity (closes the single biggest silent-failure mode in the existing plan)
- [ ] **T1 — Real snapshot, not fixtures.** `data/processed/*.csv.gz` and `manifest.json` were generated by an actual network pull against the endpoints verified in Phase 1 — not copied or derived from `backend/tests/fixtures/`. Paste `manifest.json`'s `fetched_at` timestamps, row counts, and the command that produced them.
  **If you cannot reach Elexon from this environment, this item is RED, full stop.** It is not satisfied by fixtures, no matter how many other checks pass. It becomes Tier-2 item H3 with the exact command to run. Do not generate `docs/INSIGHTS.md`, the video script's numbers, or `docs/FORM_ANSWERS.md`'s numbers from fixture data and present them as findings — fixtures are legitimate *test* inputs, but numbers derived from them are not legitimate *product* findings.
- [ ] **T2 — Leakage audit on the real snapshot.** `test_no_leakage_on_real_snapshot` passing against the **real** committed data (not the unit-test fixtures) — paste pytest output — plus one manual spot check in the Revisions explorer.

### 2.2 Build & quality (existing checks, now evidence-gated)
- [ ] `make lint typecheck test` — paste the **full** output, including coverage numbers, not a summary sentence.
- [ ] Clean-clone Docker smoke: `git clone` into a fresh temp dir → `docker compose up --build` → `scripts/smoke_docker.sh` — paste output, or mark RED per `docs/AGENT_CAPABILITIES.md` if no Docker daemon is available to you.
- [ ] `make types` then `git diff --exit-code` (generated TS types match the OpenAPI schema) — paste output.
- [ ] `vitest-axe` — zero serious/critical violations — paste output. Lighthouse only if Tier 0 found a usable headless browser; otherwise it's Tier 2.

### 2.3 Repo and content hygiene (two scripts that don't exist yet elsewhere in this document set — specify, write, and run them)
- [ ] `scripts/check_no_placeholders.sh` (new): fails on any `TODO`, `FIXME`, `XXX`, `lorem ipsum`, or an unresolved `<<...>>` token (e.g. a literal `<<VERCEL_URL>>` left in README) anywhere tracked by git. Paste output; zero hits, or each hit individually justified.
- [ ] `scripts/check_anonymity.sh` — paste output — **plus** a manual pass over anything that isn't plain text: screenshots and any images under `frontend/public/` or `docs/img/` can carry EXIF/author metadata by default (`exiftool -all= <file>` to strip, or confirm none exists).
- [ ] Repo size and composition are sane: no `.env`, no `node_modules`/`.venv` tracked. Paste `git ls-files | xargs du -ch | tail -1` and `git status`.
- [ ] `git log --oneline` shows ≥ 15 meaningful, Conventional-Commits-style entries — not a squashed history.

### 2.4 Numbers consistency (the current plan only asks for a five-number spot check; that's not enough when the entire pitch is "quantified, not vibes")
- [ ] Regenerate `docs/INSIGHTS.md` **last**, after all domain/analysis code is frozen — it must be the final content-producing step before README/video-script/form-answers are finalised, not a Phase-6 artifact that silently goes stale during Phases 7–9.
- [ ] `scripts/check_numbers_consistency.sh` (new): extracts every numeric claim (a number followed by `MW`, `MWh`, `%`, or a bare percentage) from the README "Key findings," `docs/VIDEO_SCRIPT.md`, and `docs/FORM_ANSWERS.md`, and asserts each one traces to a value in `docs/INSIGHTS.md` (exact match or a stated, consistent rounding rule). Paste output listing **every** claim checked, not a sample. A claim that doesn't trace is a bug to fix in the doc or the number — not a rounding footnote to wave away.

### 2.5 Pre-recording readiness (catches overruns *before* the human's one recording attempt, not after)
- [ ] Estimate spoken duration per section of `docs/VIDEO_SCRIPT.md` from its word count at ~130–150 wpm; flag any section whose estimate exceeds its budget (the timing table in `IMPLEMENTATION.md §8.3`) by more than 10%. Cheap, and it prevents burning the human's one take on a script that was always going to overrun.

## 4. Anonymity in the recording itself — what `check_anonymity.sh` cannot see

Before recording, the human checks each of these explicitly, not from memory (full version also in `ENGINEERING_REFERENCE.md §17.3`):

- [ ] Terminal prompt does not show a real username/hostname (`whoami` / `hostname` — change `PS1` or crop if needed)
- [ ] No file path on screen contains a real name (`/Users/<realname>/…`, `C:\Users\<realname>\…`) — clone the repo under a neutral path for the recording
- [ ] IDE/editor title bar and any "recent projects" list don't leak a real name or employer
- [ ] Browser profile name/avatar/autofill (address-bar suggestions, saved-password icon) is a neutral or fresh profile, not the human's everyday one
- [ ] Desktop wallpaper, dock/taskbar pinned apps, and any notification banners during the recording are neutral
- [ ] Voice: if anonymity is meant to extend to the speaker too, a recognisable voice is itself identifying — decide and disclose whether that's in scope; this document doesn't rule on it because the brief doesn't either

## 5. Honesty on "≤ 16 hours" and "time spent"

The brief's 16-hour cap is a **scope budget** — it tells a candidate what *not* to build, and `IMPLEMENTATION.md`'s phase table uses it that way. It is not a literal duration for an AI agent, whose build time won't resemble 16 human-hours in either direction. When `docs/FORM_ANSWERS.md` asks for time spent:
- Report the human's actual time — reviewing the agent's output, fixing what needed fixing, deploying, recording, submitting — not the agent's compute time, and not a copy of "16 h" because that's the number mentioned in the brief.
- If AI assistance substantially reduced that time, say so plainly alongside the README's AI-disclosure section (`MASTER_PROMPT.md §3` C7). That's a credibility strength here, not something to obscure.
